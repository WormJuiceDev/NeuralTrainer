# First Version Scope

## Purpose of version 1

Version 1 is not meant to be a perfect life companion.

It is meant to prove the core idea:

- a local-first companion can notice meaningful moments
- it can decide whether to stay silent, message, or ask to call
- it can communicate in a way that feels grounded and caring
- it can learn from interaction over time

Version 1 should be enough to test whether the idea feels emotionally right in lived use.

## Version 1 must do

- track location and movement at a basic useful level
- detect likely sleep windows and respect them
- store meaningful places and repeated places
- track simple weekly rhythm and meaningful deviations
- store manual reflections and boundaries
- remember whether outreach felt right or wrong
- decide between:
  - silent saved moment
  - Telegram message
  - Telegram call request
- use a local model to draft grounded outreach language
- let you inspect and edit the memory model through a desktop interface

## Version 1 must not try to do

- broad task automation
- general assistant behavior
- cloud-model dependence
- complicated tool use
- deep world knowledge
- paid services
- perfect emotional understanding
- human-level judgment
- highly polished voice calling flows

## Version 1 success criteria

Version 1 is successful if:

- it reaches out rarely but meaningfully
- its messages feel specific rather than generic
- it respects sleep and protected times
- it learns from feedback
- it helps create at least some moments of real reflection or felt companionship
- it feels more like a presence than a notification engine

## Version 1 communication scope

Primary:

- Telegram messages
- Telegram call requests

Optional if realistically possible without cost:

- Telegram-based live call behavior or handoff

If live calling is not practical in version 1, the system should still work meaningfully through message plus call invitation.

## Version 1 memory scope

Keep:

- meaningful places
- recurring rhythms
- recent emotional context
- outreach history
- manual reflections
- boundaries

Do not attempt yet:

- broad autobiographical memory
- deep long-form life history modeling
- heavy psychological interpretation

## Version 1 model scope

Use the local model for:

- phrasing
- interpretation
- reflective framing

Do not use the local model as the main system controller.

The hard rules and judgment boundaries should remain deterministic code.

## Version 1 input scope

Use:

- location
- movement and stillness
- time and sleep heuristics
- manual reflections
- response feedback

Defer:

- weather
- calendar
- biometrics
- rich external event systems
- advanced environmental sensing

## Version 1 design discipline

If a feature makes the system:

- noisier
- more complicated
- more dependent
- more “assistant-like”
- less respectful

then it should probably not be in version 1.

## Final test for version 1

At the end of version 1, the question is not:

- "How many features does it have?"

The real question is:

- "Did it ever reach out in a way that genuinely made life feel more noticed, shared, or meaningful?"
