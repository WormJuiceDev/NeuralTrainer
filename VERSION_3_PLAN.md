# Version 3 Plan

## Purpose

Version 3 should make the companion wiser before it becomes more powerful.

Version 1 proved the core idea.

Version 2 made memory and learning more trustworthy.

Version 3 should deepen discernment.

It should help the system:

- understand its own evidence better
- explain its reasoning more clearly
- distinguish stronger moments from weaker ones more reliably
- stay grounded without becoming invasive

This is not the version for emergency interruption yet.

The next intended build version after this one is live voice and actual conversation, before long real-life validation begins.

---

## Version 3 goal

Build a companion that has better contextual depth and better restraint.

That means:

- richer memory provenance
- better place and rhythm interpretation
- stronger distinction between routine, anomaly, rest, and meaning
- better explanation of why the system thinks something matters
- better silence decisions before adding more expressive channels

---

## What Version 3 should add

- clearer evidence trails for memories and saved moments
- better interpretation of repeated places and weekly patterns
- richer decision metadata for why silence or outreach happened
- more nuanced distinctions between:
  - celebration
  - retreat
  - habit
  - irregularity
  - emotional weight
- stronger local review surfaces for meaning and provenance
- more automated scenario coverage for discernment logic

---

## What Version 3 should not add

- emergency safety interruption
- live voice calling
- autonomous tool use
- broad assistant behavior
- cloud dependence
- calendar or weather expansion unless a later version truly needs it

---

## Core principle

Version 3 should make the companion:

- more interpretable
- more grounded
- more discerning

Not:

- more intrusive
- more dramatic
- more reactive

---

## Workstream 1: Memory Provenance

### Purpose

Make memory feel earned because the system can show what shaped it.

### Build

- show memory source more clearly
- show reinforcement timing and source
- show whether a memory came from:
  - repeated place evidence
  - manual reflection
  - outreach feedback
  - call-request outcome
- show what would make a memory strengthen, fade, or stay tentative

### Done means

- a person can look at a memory item and understand why it exists

---

## Workstream 2: Better Context Interpretation

### Purpose

Make the system better at telling the difference between ordinary rhythm and meaningful deviation.

### Build

- richer repeated-place interpretation
- stronger rhythm-baseline comparison
- better handling of “this week” context
- better differentiation between:
  - long pause because of routine
  - long pause because of significance
  - repeat visit because of habit
  - repeat visit because a place is gaining meaning

### Done means

- the saved moments feel more plausible and less blunt

---

## Workstream 3: Decision Explainability

### Purpose

Make the system’s judgment inspectable before any later voice or safety layer exists.

### Build

- clearer “why messaged” explanation
- clearer “why stayed silent” explanation
- better decision metadata in the review surface
- stronger separation of:
  - confidence
  - boundary suppression
  - cooldown suppression
  - meaning-based promotion

### Done means

- the user can understand the system’s judgment without reading code

---

## Workstream 4: Automation and Simulation

### Purpose

Keep Version 3 fast to build by proving discernment changes through local automation instead of waiting on real-life tempo.

### Automate aggressively

- repeated-place meaning growth
- stronger vs weaker rhythm-break scenarios
- stable routine that should stay silent
- celebratory vs heavy context distinction where possible
- provenance visibility checks
- no-op decision cases
- clearer suppression-reason checks

### Keep manual review only for

- whether the interpretation feels fair
- whether the explanations feel clear
- whether the system still sounds grounded

### Done means

- most Version 3 discernment work is regression-testable

---

## Suggested build order

### Milestone 1: Memory provenance surface

Build:

- richer memory explanation
- detail panel
- reinforcement / decay explanation

Prove:

- memory review feels understandable

### Milestone 2: richer place and rhythm interpretation

Build:

- better place-meaning transitions
- stronger rhythm reasoning
- more nuanced saved-moment distinctions

Prove:

- moments feel less generic and less noisy

### Milestone 3: decision explainability

Build:

- clearer decision detail surfaces
- better silent-outcome inspection
- evidence-aware suppression reasoning

Prove:

- the system can explain itself honestly

### Milestone 4: automation completion

Build:

- Version 3 simulation scenarios
- additional regression tests
- one-click suite coverage for discernment changes

Prove:

- Version 3 can be iterated quickly without real-life waiting

---

## Version 3 success test

Version 3 is successful if:

- the memory model is easier to understand
- saved moments feel more plausible
- silence decisions feel more explainable
- the system distinguishes more clearly between routine and meaning
- the companion still feels respectful

---

## Final test

At the end of Version 3, the real question is:

- "Does the companion now seem wiser in what it notices and what it leaves alone?"

If yes, then the system is in a stronger position to build Version 4: voice / live conversation.
